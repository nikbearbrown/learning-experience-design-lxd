## STEP 2 — RUNNING PROJECT OPTIONS

### Project Option 1: The Redesign Dossier (formalizes the book's own studio thread)
**What it is:** The learner picks one real learning experience they can touch (their course, their company's onboarding, a product they use) and builds the complete evidence-disciplined redesign portfolio chapter by chapter — with AI tools doing the legwork and the learner doing the judgment.
**Final deliverable:** A hiring-loop-grade redesign portfolio: learner research, journey map, co-design record, tested prototype, variability audit, motivation/modality/AI decisions, measurement plan, evaluation, decision trace.
**Why it fits this book:** It IS the book's Track B studio thread — the five-part blocks operationalize the existing Studio Assignments with explicit AI judgment training. Zero redundancy, maximum reinforcement; the milestones (Ch4, 8, 13, 15) already exist.
**Adaptability:** A Finance learner redesigns the CFA-prep course or the bank's compliance training; a Branding learner redesigns a brand-academy onboarding; an engineer redesigns the team's tooling tutorial.
**Tool path:** Claude Project (persistent context for the dossier) + Cowork for assembling the portfolio files; Claude Code optional for the instrumentation chapter.
**Validation opportunities:** AI-generated personas hallucinating learner attributes (Ch5); journey maps invented rather than observed (Ch6); misquoted effect sizes in evidence summaries (Ch1, 10, 11); AI happily drafting the equity audit it cannot actually perform (Ch9); the evaluation chapter's two-register conclusion softened by the model's agreeableness (Ch14).

### Project Option 2: The Public Evidence Audit
**What it is:** The learner picks one famous learning product (Duolingo, Khanmigo, a corporate LMS, a MOOC) and builds a publishable evidence audit, one audit layer per chapter.
**Final deliverable:** A teardown report + scorecard: engagement-vs-learning audit, load audit, motivation mechanics, journey reconstruction, variability/equity audit, AI-feature scaffold/crutch classification, measurement-claims audit, and a final verdict with confidence levels.
**Why it fits this book:** Pure diagnosis — exercises the book's evidence discipline against a real market artifact; naturally publishable (Substack/portfolio piece).
**Adaptability:** Finance learner audits a financial-literacy app; Branding learner audits a creator-economy course; HR learner audits the company's compliance vendor.
**Tool path:** Claude chat for analysis + Cowork for the report build; web research throughout.
**Validation opportunities:** the richest of the four — AI will confidently invent product features, misattribute studies, and fabricate vendor claims; every chapter's audit layer requires verifying AI claims against the actual product and primary sources. Weakness: no making, only judging — Ch7 (co-design) and Ch8 (prototyping) become simulated rather than real.

### Project Option 3: The Design-Decision Field Guide
**What it is:** The learner builds a personal, web-published field guide of evidence-grounded decision tools — one decision card per chapter (engagement-trap check, load audit, motivation decision tree, gamification decision protocol, modality decision, AI guardrail spec, measurement picker...).
**Final deliverable:** A single-file HTML field guide (built with Claude Code/Cowork) the learner actually uses at work — the book compressed into fifteen working instruments.
**Why it fits this book:** Each chapter's mechanism becomes a reusable tool; strong CLI-exercise spine (the guide is code); the validation exercises check whether each card encodes the evidence correctly — wrong cards are durable misinformation.
**Adaptability:** Cards re-skinned with domain examples; a Finance version cites compliance-training cases, a Branding version cites campaign-academy cases.
**Tool path:** Claude chat for card content, Claude Code/Cowork for the build — the strongest Exercise 4 path of the four options.
**Validation opportunities:** evidence fidelity per card (does the gamification card carry the negative-effect studies or just g = 0.782?); scope creep (AI adding plausible-but-unsourced rules); the Ch9 card forcing the three-justification-logics split AI reliably flattens.

### Project Option 4: The Micro-Course in a Box
**What it is:** The learner designs and partially builds a real 4-week micro-course in their own domain, adding one design layer per chapter.
**Final deliverable:** A teachable package: outcomes, learner research, journey map, one prototyped + tested lesson, variability audit, motivation/modality/AI decisions, instrumentation plan, evaluation plan, and a syllabus.
**Why it fits this book:** Generative rather than diagnostic — the learner experiences every trade-off from the maker's side; closest to what working LXDs actually ship.
**Adaptability:** Total — the micro-course IS the learner's domain ("Reading a 10-K," "Brand Voice in 4 Weeks," "Intro to Soldering").
**Tool path:** Claude Project (course context) + Cowork (course files); Claude Code for the Ch13 instrumentation stub.
**Validation opportunities:** AI-drafted lesson content that is fluent but pedagogically inverted (theory-before-task); invented citations in course materials; assessment items that don't test the stated outcome; the Ch12 exercise where the learner must specify the course's own AI policy.
